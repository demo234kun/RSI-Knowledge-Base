### A3.2 训练数据底座 = Harness 轨迹（Agent-Native）

- **语料核心**：Routing Harness 在 Agent 执行场景中产生的**结构化轨迹** + 公开数据。
- **轨迹含 8 类字段**：任务请求、能力需求评估、路由选择、模型响应、工具调用、环境反馈、错误与恢复路径、最终完成状态。
- **相比问答语料多三个信息维度**：能力需求、执行决策、环境结果。
- **失败轨迹的价值**：被中途替换的失败轨迹同样保留——"最终答案说明怎么做对，失败与修复过程说明哪里容易出错、出错后如何恢复"。
- **清洗两闸**：① 结构检查（请求/模型回复/工具调用/环境结果正确对应）；② **六维质量评估**——是否完成任务目标 / 是否遵循指令 / 工具使用是否合理 / 结论是否有证据支撑 / 遇到错误后是否恢复 / 是否在正确时机终止。
- **Agent-Native 取向**：训练目标从第一轮就指向任务完成，而非"先通用训练、再补 Agent 适配"。

### A3.3 Agentic Post-Training = 路由信号双用途

- **C0-C3 四档服务**：C0=边界清晰的低风险请求；C1=通用默认档；C2=多步推理与执行；C3=最高能力/最高可靠性。
- **三段式拆解**：路由记录拆成 `预测（路由器估计的能力需求）— 行动（策略实际选择的档位）— 结果（任务最终结果）`。
- **训练侧只用"预测"排课程**；**"结果"字段输出能力短板信号**：哪些子场景反复失败、哪些环节恢复成本高、哪些能力档位供给不足。
- **Capability-Guided Data Allocation（能力引导的数据配比）**：短板信号 → 调整下一轮训练数据配比 → 形成"评测反馈 → 数据配比 → 更新模型"闭环。
- 一句话：**在线阶段判断"这个任务该由谁完成"，离线阶段决定"模型应先学习哪些能力"。**

### A3.4 RSI：Data-RSI 与 Model-RSI（单轮闭环）

| 环节 | 机制 |
|---|---|
| **Data-RSI** | 模型在 Harness 中持续执行任务，每次路由/工具调用/失败恢复/最终结果都产生新结构化记录 → 筛选后成为后续训练候选材料（随系统运行自然增加） |
| **Model-RSI** | 根据评测结果定位能力短板 → 调整下一轮训练数据分布 → 更新模型 → 新模型放回 Harness 模型池 |

- **核心句**："模型从执行经验中学习，并通过新的执行过程为下一轮训练提供反馈。"
- **官方定位声明**：当前 NeoHorse-1 **尚不能被视为完整的 RSI 系统**——本次验证的是一次"执行—评估—选择—更新"闭环；**信号编译、奖励设计、训练流程仍由人类设定**；多代模型能否持续获得稳定增益**有待后续实验**。
- **两层验证价值**：① 结构化执行经验可以转化为模型训练材料；② 同一 Harness 内可以完成一次 RSI 工程闭环。

### A3.5 业务闭环（OpenSquilla）

> OpenSquilla 承接 Agent 任务 → Routing 识别各环节适配的模型 → TokenRhythm API 输出能力 → 任务反馈用于迭代路由与模型 → 更新后的模型重新进入模型池。

### A3.6 部署要点（可直接执行）

- 4B/9B 均为 **BF16**，原生上下文 **262,144 tokens，可扩至 1,010,000**。
- 下载：`modelscope download --model TokenRhythm/NeoHorse-1-4B --local_dir ./NeoHorse-1-4B`
- **SGLang 0.5.17**（评测版本）：
  ```bash
  python3 -m sglang.launch_server --model-path ./NeoHorse-1-4B \
    --served-model-name neohorse-1-4b --host 0.0.0.0 --port 30000 \
    --context-length 262144 --reasoning-parser qwen3 --tool-call-parser qwen3_coder
  ```
- **vLLM**：
  ```bash
  vllm serve ./NeoHorse-1-4B --served-model-name neohorse-1-4b \
    --host 0.0.0.0 --port 8000 --max-model-len 262144 \
    --reasoning-parser qwen3 --enable-auto-tool-choice --tool-call-parser qwen3_coder
  ```
- **OpenAI 兼容 API**：`base_url="http://localhost:8000/v1"`（vLLM）或 `:30000/v1`（SGLang），`api_key="EMPTY"`，直接 `client.chat.completions.create(...)`。

## A5. 与知识库的交叉印证

- **P12 卡批判 (b)"能力引导分配可能塌缩"**：本文给出反证细节——`结果`字段专门输出"供给不足的能力档位"，说明配比调整是**面向短板而非面向高能力子域**，塌缩风险部分被机制对冲；但仍缺多代实验证明。
- **P09 内省阈值**：本文明确"信号/奖励/训练流程仍由人类设定"→ NeoHorse 是**受监督的自改进**（人在环内守门），天然避开 P09 的纯自评退化路径；代价是"递归"程度有限（R 的自我指涉弱）。
- **P02 GVU 映射**：G=路由选择生成者，V=结构验证+六维评估+基准，U=课程 SFT+蒸馏，且 U 的输入 = 上一轮 V 的反馈 —— 教科书级 GVU 实例。
- **金融应用区**：`表现加权采样`设计 = Capability-Guided Data Allocation 的免训练版本（以回测分数当"结果字段"）。

## A6. 批判性解读

- ✅ **优点**：a) 把 RSI 闭环的**每个环节都落到可执行粒度**（字段、档位、评估维度、配比），是目前公开渠道最完整的"执行→训练"管线说明；b) 诚实声明"非完整 RSI"，未夸大；c) 开源授权 Apache-2.0，4B 一张消费卡可部署。
- ⚠️ **局限**：a) 六维评估仍依赖模型自评/人工设定→有 [P08 自洽≠正确](../论文/cards/P08_SelfRewardingTheory_2601.22513.md) 风险残余（文章未披露评估器是判分模型还是人工）；b) 无数据量/过滤率/训练成本披露→复刻成本难精确预估；c) 配比调整的**具体算法未公开**（只说"调整"）；d) 单轮实验，跨代稳定性未验证。
- 🔎 **复刻启示**：文章证明完整闭环需要 **Harness（执行场）+ 路由（评估选择）+ 轨迹管线（数据）+ 再训练（更新）**四件套；官方仓库不含训练代码→复刻必须自建数据管线（见 Part B）。

## B2. 复刻对象与边界（先定义清楚）

| 复刻什么 | 说明 |
|---|---|
| ✅ 复刻**闭环方法** | 执行→评估→选择→更新 的四环节回路（无需完全相同的数据/规模） |
| ✅ 复刻**数据管线思路** | 轨迹 8 字段结构化 + 两闸清洗（结构检查+六维评估） |
| ✅ 复刻**能力引导配比** | 用回测/评测分数当"结果字段"→调整下轮训练分布 |
| ❌ 不复刻模型权重 | 直接使用已发布 4B/9B 权重为起点（复刻"更新"一步 = 在其上加一轮后训练） |

## B3. 最小成本复刻方案（分两步）

### Step 1 · 部署层复刻（¥0–数百，1 天）— 复现"模型可跑、可并入 harness"

| 组件 | 做法 | 成本 |
|---|---|---|
| 权重 | `modelscope download` 4B（≈4.2GB）| ¥0（免费下载） |
| 推理 | SGLang 0.5.17 / vLLM（命令见 A3.6）| 自有 16–24G 显卡 ¥0；云 GPU 时租约 ¥2–5/h |
| 无卡替代 | 直接调 [ModelScope 创空间/API](https://www.modelscope.cn/models/TokenRhythm/NeoHorse-1-4B)（若上线） | ¥0–数百 |
| 验收 | `examples/chat.py` + `tool_call.py` 跑通；OpenAI API 兼容调用返回 | — |

### Step 2 · 闭环层复刻（¥数百–数千，2–4 周）— 复现"执行→评估→选择→更新"

| 环节 | 最小成本实现 | 对照官方 |
|---|---|---|
| **G 执行场（Harness）** | 自建轻量工具调用环境（2–4 个工具：搜索/代码执行/文件读写；给模型 `--tool-call-parser qwen3_coder`）| OpenSquilla 替代 |
| **路由（评估→选择）** | 规则路由替代训练路由：按 `C0-C3` 启发式（任务复杂度关键词/工具数/上下文长度阈值）|| C0-C3 档位思路保留 |
| **轨迹收集** | 每轮记录 8 字段 JSONL（请求/能力需求/路由/响应/工具/反馈/错误/结果）| Data-RSI 数据面 |
| **清洗** | 结构检查（脚本对照字段）；六维评估用 LLM-as-judge（本地 4B 即可）打分 | 两闸清洗 |
| **配比调整** | 按"结果字段"统计：反复失败的子场景 → 下轮该子场景采样权重 ×2 | Capability-Guided Allocation |
| **更新** | 一轮课程 SFT：LLaMA-Factory 在 4B 权重上 LoRA 微调（消费卡 24G 可跑 1–2 天）| 课程 SFT（官方为全量三阶段，LoRA 为降本替代） |
| **回环** | 新模型放回 harness 模型池 → 再执行 → 验证 → 迭代（预算内） | Model-RSI |

**成本汇总**：数据收集=本地推理电费；清洗=本地 LLM 评判；训练=LoRA（¥0 自有卡 / ¥数百-千云卡）；**总计最乐观 ¥0 – 数千 / 最典型 ¥500 内（API 清洗+云卡短租）**。

## B4. 验收标准（怎么算复刻成功）

1. **部署复刻**：OpenAI 兼容 API 返回工具调用 JSON 格式正确（tool_call 示例通过）。
2. **闭环复刻**：在一个 held-out 任务集上，**第 2 轮模型 ≥ 第 1 轮模型**（同一评测集，逐轮独立评测，防 [P09](../论文/cards/P09_内省阈值_2607.04277.md) 退化误判）。
3. **配比生效**：人为注入某种高频失败子场景 → 下一轮该场景数据占比上升（机制可观测）。

## B5. 风险与对策（金融区同款纪律）

| 风险 | 对策 |
|---|---|
| 轨迹污染（自评六维被 4B 判分器放大幻觉） | held-out 人工抽查 ≥ 10%，或换更强判分 API |
| LoRA 更新增益为负（伪退化） | 保留上一代 checkpoint，逐代独立评测，负增益即回滚（内省阈值纪律） |
| 评测集泄漏（轨迹里含评测任务） | 评测任务不进轨迹池（写保护） |
| 配比塌缩（全压向单一场景） | 配比 cap（单场景 ≤ 3×）、多样性正则 |
