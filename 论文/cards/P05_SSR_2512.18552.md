## 一句话结论

> **SSR（Self-play SWE-RL）**：让单个 LLM 智能体在**沙箱真实代码仓库**中，通过自我博弈（自我注入 bug → 自我修复 bug）生成训练信号，仅用"源码 + 已装依赖"、**完全不需要人工标注的 issue 或测试**——SWE-bench Verified **+10.4**、SWE-bench Pro **+7.8**，且全程优于"人类数据基线"。

## 问题背景

- 当前软件智能体（SWE-agent）的训练数据 = 人类 GitHub issue/PR + pass-to-pass / fail-to-pass 测试，**深度依赖人类知识或人工策展**。
- 论文论点：这一依赖是通向"软件超智能"（superintelligent software agents）的根本障碍——智能体学不到人类没写过的 bug。

## 方法

1. **数据假设最小化**：仅需沙箱化仓库（源码 + 已装依赖）；无人工 issue、无人工测试标注。
2. **自我博弈训练回路**：
   - 智能体**注入 bug**（agentic bug injection，在真实代码库上制造缺陷）
   - 每个 bug 由**测试补丁（test patch）形式化定义**（而非自然语言 issue 描述）——评估信号自动、可验证
   - 智能体再**修复该 bug**，经 RL 训练，bug 复杂度随训练自动递增（难度课程自举）
3. **验证**：在 SWE-bench Verified / Pro（自然语言 issue，自博弈中从未出现）上评测泛化。

## 关键结果

| 评测 | 提升 |
|---|---|
| SWE-bench Verified | **+10.4** |
| SWE-bench Pro | **+7.8** |
| 与人类数据基线对比 | 整个训练轨迹**一致占优** |

- 结论定位："智能体可从真实软件仓库自主积累海量学习经验……最终实现超越人类能力的系统构建/求解/创造。"——软件领域的 RSI 宣言。

## 与 RSI 知识库的关系

- **"训练期自迭代 × 自我博弈"方法族的工程标杆**（P01 分类：训练期 340 篇中自我博弈子线的代表；GVU 框架 [P02] 的 Updater=RL 实例）。
- 与 LADDER [P04] 形成互补：LADDER 解决"没有难度标注"，SSR 解决"没有人类 bug/测试标注"——两条去人工标注的自改进路线。

## 解读与批判

- ✅ **优点**：a) 数据前提极简（只要真实代码库）→ 训练数据可近乎无限扩展；b) 用"测试补丁"形式化 bug 让验证信号干净；c) ICML 2026 接收，实验严谨。
- ⚠️ **局限**：a) 自我注入 bug 的多样性/难度上界依赖注入器本身——可能学不到"人类风格"的复杂缺陷（论文成果是非对称问题）；b) 评测（SWE-bench）本身仍来自人类知识，self-play 能覆盖的"新颖性"边界需更多证据；c) 是"软件领域"的 RSI 路线，不含自我改进算法层面的参考性（对照 P03 自参考重写）。
